# LLM vs. Deterministic Responsibility Matrix — `structured_claim_shadow`

Grounded in `docs/specs/development_plan_v1.0_reference_index.md` (Development
Plan v1.0 §5.1, `SOURCE_FROZEN`), `docs/adr/ADR-008-structured-output-adapter-shadow.md`,
and `docs/specs/structured_output_adapter_shadow_contract_v1.md`
(`APPROVED_PROJECT_DECISION`). None of these documents were modified to produce
this matrix.

Development Plan §5.1 requires: natural-language Agent output becomes a
standard Claim schema; downstream consumes structured JSON; required
identity/Claim/Evidence fields are retained; factors are best-effort; entities
may be empty; confidence is bounded; malformed LLM JSON fails soft without
crashing the run. It does **not** require every candidate boundary, source
span, or identity field to be *proposed by the model* — ADR-008 §Context is
explicit: "It does not say every candidate boundary must be generated by an
LLM." ADR-008 Decision §4 is equally explicit that "the deterministic
validator is the sole Shadow admission authority," and §5 that
`shadow_claim_id` is "caller-generated ... Model-supplied IDs are ignored."
This matrix is a direct application of those two already-approved decisions to
the request/response wire shape, not a new policy.

## What the model is actually responsible for (open-language understanding)

| # | Responsibility | Where this is already established | v2 request field(s) that serve it |
|---|---|---|---|
| 1 | Deciding what content constitutes a real Claim | Shadow contract §Candidate segments: "may retain, merge... omit... return no Claims" | `agent_report` (full text, read once) |
| 2 | Claim boundary (where one Claim starts/ends) | ADR-008 Decision §2 | `agent_report` + optional located-candidate offset hints |
| 3 | Whether to split one candidate into several Claims | ADR-008 Decision §2; v1 prompt CLAIM RULES (unchanged in v2) | fixed instruction |
| 4 | Whether to merge adjacent candidates | ADR-008 Decision §2 | fixed instruction |
| 5 | Faithful paraphrase of the Claim | Shadow contract §Bundle schema: "Claim may be a concise faithful paraphrase" | model output `claim` field |
| 6 | Which source spans support the Claim | Shadow contract §Stable Claim identity / §Bundle schema | model output `source_spans[].start/end` |
| 7 | Entity recognition | Development Plan §5.1 ("entities may be empty" — best-effort, not deterministic) | model output `entities` |
| 8 | Factor candidate selection | Development Plan §5.1 ("factors are best-effort") | model output `factors`, scoped by `factor_vocabulary` |
| 9 | Direction judgment | Not code-derivable from text alone | model output `direction` |
| 10 | Abstention when unsupported | ADR-008 Decision §2 ("or abstain") | model output `abstentions` |

These ten are genuine open-language understanding tasks. Nothing in v2 removes
or narrows any of them — the full report is still sent (once), and the model
still has complete freedom to split/merge/omit/abstain exactly as today.

## What the model is explicitly NOT responsible for (deterministic code)

| # | NOT model responsibility | Why | v1 defect (asked anyway) | v2 fix |
|---|---|---|---|---|
| 1 | SHA-256 of the report | Pure function of caller-known text | Prompt asks model to "copy exactly" `source_report_sha256` | Caller splices it in; never asked of the model |
| 2 | Stable Claim ID | ADR-008 §5: "Model-supplied IDs are ignored" | v1 already ignores model IDs (`shadow_claim_id=""`) — already correct, unchanged | unchanged (already correct) |
| 3 | Run identity generation | Caller-owned per `validate_shadow_bundle`'s `expected_identity` check | Prompt asks model to "copy exactly" `run_id` | Caller splices it in |
| 4 | Source hash | Same as #1 | as #1 | as #1 |
| 5 | `exact_quote` copying | `report[start:end]` is a pure function once offsets are known; `validate_shadow_bundle._validate_source_spans` already independently recomputes and enforces it | v1 asks the model to echo 1,958 chars of quotes it must get byte-perfect | Caller computes `report[start:end]`; model never asked |
| 6 | Span-bounds validation | `_validate_source_spans` is the sole authority (start≥0, end>start, end≤len(report)) | n/a — validator already owns this, unchanged | unchanged (already correct) |
| 7 | Evidence-provenance verification | `_evidence_is_provenanced` is the sole authority | n/a — validator already owns this, unchanged | unchanged; v2 additionally *constructs* `evidence` deterministically (bounded join of `exact_quote`s) instead of asking the model for a separate `evidence` string |
| 8 | Factor-vocabulary legality check | `validate_shadow_bundle` checks `factors ⊆ factor_vocabulary` | n/a — validator already owns this, unchanged | unchanged |
| 9 | Duplicate Claim-ID detection | `validate_shadow_bundle` (`seen_ids`) | n/a — validator already owns this, unchanged | unchanged |
| 10 | Schema admission | `validate_shadow_bundle` is "the sole Shadow admission authority" (ADR-008 §4) | n/a — unchanged in v2: same function, same `comqutor.structured_claim_shadow.v1`, byte-for-byte | unchanged |
| 11 | Production authority / Replay metadata | ADR-008 Non-goals; `shadow_only=true`, `production_authority=false` are caller-owned invariants (`structured_output_shadow.py` sets them post-validation regardless of model output) | n/a — unchanged | unchanged |

## Net effect

Every item the model is asked to do in v2 is a strict subset of what
Development Plan §5.1 / ADR-008 / the shadow contract already say is the
model's job. Every item removed from the *wire payload* (both request-side
duplication and response-side echo-back) was already, independently,
deterministic-code-owned authority before this audit — the audit did not
discover new authority to take away from the model; it discovered that the
current prompt/schema were asking the model to *carry data* (IDs, hashes,
quotes) that the deterministic layer already owns and independently verifies.
Removing that carrying burden changes nothing about who decides what — it only
changes how many bytes travel over the wire to do it.
