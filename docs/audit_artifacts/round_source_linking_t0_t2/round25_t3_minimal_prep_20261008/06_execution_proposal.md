## 6. 预算记账规则

- 计数单位是**实际发出的 Provider 请求**。成功、失败、超时、截断都算一次。本地拒绝的请求（输入超限）没有发出，不算。
- 每个任务各用一个生产网关，它的调用预算（`max_calls`）按尝试逐次预留。两层重试都是 0，所以上限就是该任务最多能发出的请求数，超出部分不会发出，记为任务失败（budget）。
- 用量只从每个回复自带的 usage 字段读取。没有 usage 的请求（例如超时）记为"用量缺失"，**不估算**。
- 不给美元总额。参考数据：
  - 仓库价目表（deepseek-v4-flash，每百万 tokens）：非高峰 0.15 / 0.60 美元，高峰 0.30 / 1.20 美元。
  - Alpha 单次实测：prompt ≤2,236 tokens，补全 p50 267 / p95 2,400 / 最大 8,566。
  - 方向请求从未记录过用量。
  - 内容核查现在的 payload 比 Phase C 大，不做估算。

  执行后按实际 usage 汇总。**任何美元数字都不是成本保证。**
- 内容核查任务不进入语义调用账本：`content_support_verification` 不在 `llm_runtime.contracts.SEMANTIC_TASKS` 里，本轮发现。驱动因此另存每次请求的尝试记录（`task_audit.json`），记账不依赖账本。
