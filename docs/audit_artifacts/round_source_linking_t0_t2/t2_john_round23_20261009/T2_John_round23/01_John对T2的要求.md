## 四、T2：完成规则执行，不再只维护规则副本

### 1. 当前问题

现有 YAML 列出了六类语义和 16 条“标的—允许冲突”配置，但自身注明不代表实现已经对齐；最新交付仍承认 A102__A304、A201__A304 与 taxonomy 存在差距。

这项是上一轮已经明确要求的工作，本轮必须实际关闭。

### 2. 具体实现要求

**第一，补齐已确认的两组 taxonomy 关系。**

把 A102__A304、A201__A304 作为有条件可评估的关系补入实际 taxonomy，并更新版本、变更记录及测试。

“允许评估”不等于自动成立，更不等于必须成为主冲突。

**第二，落实六类规则的执行映射。**

对以下六类规则逐项说明配置来源、适用对象、执行函数、触发条件和判定结果：

must_detect_if_evidence_present、should_detect_if_supported、conditional_only、do_not_force、allowed_main_conflicts、forbidden_dominant_without_strong_evidence。

已有等价字段可以保留，不必为名称重写模块；但不能只列出六个名字，而没有实际执行内容。

**第三，统一正式验收入口。**

正式验收显式读取指定规则文件和 taxonomy，不允许静默回退到旧版本。程序输出解析后的 effective_rules，所有验收表和摘要从同一结果生成。

规则缺失、类型未实现或 taxonomy 不兼容，应输出配置／执行错误，不能改成 NOT_APPLICABLE 后继续 PASS。

**第四，保持研究与 Gold 验收分离。**

Gold 标签不能作为目标答案输入研究 Agent，也不能为了符合允许列表而改写研究输出。

例如，NVDA 当前的 A304__A601 继续保留为待审核结果；QQQ 新 run 的 PASS 不能替代旧 run 尚未关闭的复核。

### 3. 必须提供的自动测试

| 测试场景 | 预期行为 |
|---|---|
| 有明确支持证据，却漏掉必须识别的 Alpha | 验收能够发现漏检 |
| 没有支持证据 | 不强制激活 Alpha 或生成冲突 |
| 只有反驳、引用或背景文字 | 不当成该 Alpha 的有效支持 |
| 必需规则缺失或无法执行 | 报错，不产生正式 PASS |
| 同源证据增加多份重复表达 | 不重复抬高证据强度 |
| 实际冲突不在标的验收列表 | 保留研究输出，转入复核，不改答案 |
| 同一输入做纯 replay，只更换执行编号 | 不因 run_id 变化产生无依据的研究结论变化 |

测试可以使用明确标注的合成 fixtures，但不能把它们计为真实市场验证样本。

**验收标准：交付代码 diff、有效规则、原始测试结果，以及六个历史标的的逐条规则判定。不是只交一份写着 FROZEN 的 YAML。**
