## 1. 五项工程成果

**① Conflict 页（`ConflictEvidenceSections` 接入已有的 “View basis”，复用同一份核验结果）**
* 每条证据（bull / bear / counter）一个 “View basis”；点击才取数。面板分两块：**Historical use in this run (as saved)** —— 读自该 run 的 `conflicts.json`，逐条列出它在哪些冲突的哪一侧、冲突的 admitted / level / score，**并写明“不被下面任何内容改变，不重新评估”**；**Current basis** —— 旧 run 显示 `NOT_LINKED` 加一句中性说明：“该 run 保存时尚无来源关联字段，所以今天无法显示来源依据；这描述的是保存了什么，**不是**对该声明‘错误’或‘当时没有依据’的结论”，并说明下面 Alpha 匹配 / 立场 / 官方计分是该 run 自己保存的结果，只有来源支持一栏按今天的字段读取。
* 不改写历史：trace 只读；测试证明构建 trace 不创建 / 修改 / 删除任何文件、不改 `conflicts.json`；面板文字里除这句否定句外不含 wrong / incorrect / invalid / baseless / no basis（后端与前端测试都断言）。
* 真实数据（`d5b60b8a` 的 A301__A304，admitted / low / 14.2594）：浏览器里主冲突卡片 34 个 “View basis”（15 / 17 / 2，与保存的清单一致）；每侧各开一条，历史采用文字与保存值逐项一致；整个历史 run 目录 24 个文件前后哈希相同。实际观察到的保存事实照实显示：声明 90 在同一个已保存冲突里**既是 bear 又是 counter**，面板两条都列出，不替读者选。
