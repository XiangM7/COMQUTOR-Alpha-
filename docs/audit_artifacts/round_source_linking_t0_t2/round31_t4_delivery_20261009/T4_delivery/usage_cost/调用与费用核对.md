**三方对账（Week 2）**：网关预算占用 1204 次 = 线路审计转发的 HTTP 请求 1204 个 = 账本中的 HTTP 尝试 1204 次。

**响应**：线路审计收到 1198 个响应，状态码全是 200。
- 1204 − 1198 = 6，即 6 个超时请求没有任何响应记录。**这个 6 和"输入超限未发送"的 6 不是一回事，两者不要混淆。**
- 第 7 个超时请求（适配器 attempt 2）比较特殊：

- **耗时**：账本记录的 7 个适配器超时调用，4 个约 91 s，3 个约 45–46 s。配置是共享 45 s，每个请求头里都是 `x-stainless-read-timeout: 45.0`。约 91 s 的原因本包没有核查。

### 1.2 内容核验："61＋79＋95＝235"与"236 次请求"不是同一个总数

两个数统计的对象不同：

| 数 | 统计对象 |
|---|---|
| 235 | 按**最终状态**数 claim：SUPPORTS 61、CONDITIONAL 79、PENDING_REVIEW 95 |
| 236 | **实际发出的内容核验 HTTP 请求**数，每个请求核验 1 条 claim |
| 241 | 内容核验账本记录数：236 个已发送，加 5 个因输入超过 60,000 字符而**没有发送**的 |

逐格对账（每条 claim 的最终状态 × 有没有发出请求）：

| 最终状态 | 发出请求，模型返回被接受 | 发出请求，模型返回被拒（`rejected`） | 输入超限，没有发送 | 没有请求（其他方式） | 合计 |
|---|---|---|---|---|---|
| SUPPORTS | 56 | 0 | 0 | 5（`AUTOMATED_DATA_FACT_VERIFIED`，确定性核对，没有模型调用） | 61 |
| CONDITIONAL | 79 | 0 | 0 | 0 | 79 |
| PENDING_REVIEW | 39（模型判 INSUFFICIENT） | 51（引文在来源中找不到 48，`malformed_response` 3） | 5（标签记为 `malformed_response`，不准确：根本没有发出） | 0 | 95 |
| BACKGROUND | 9 | 0 | 0 | 0 | 9 |
| OPPOSES | 2 | 0 | 0 | 0 | 2 |
| NOT_APPLICABLE | 0 | 0 | 0 | 705（未链接 615；sentiment 无来源登记 90） | 705 |

- **差额**：235 中有 10 条没有发出请求（5 + 5）；另有 11 个已发送的请求，最终状态不在这三类里（BACKGROUND 9、OPPOSES 2）。所以 235 − 10 + 11 = 236。
- **79 条 CONDITIONAL 的构成**：
  - 26 条是模型直接判 CONDITIONAL；
  - 53 条是模型判 SUPPORTS，但披露了 MATERIAL 级未支持部分，按既有映射降为 CONDITIONAL。53 条中 DIRECT_FACT 31、DERIVED_CALCULATION 16、GROUNDED_INFERENCE 3、SEMANTIC_PARAPHRASE 3。

### 1.3 费用口径

| 项 | 内容 |
|---|---|
| 价格来源 | `comqutor_alpha/llm/cost_basis.py` 中的价格表，2026-09-30 查询 `https://api-docs.deepseek.com/quick_start/pricing`。**本轮没有在线查价** |
| 单位 | 美元 / 每 100 万 token |
| deepseek-v4-flash 闲时 | 输入（缓存未命中）0.15，输入（缓存命中）0.003，输出 0.60 |
| deepseek-v4-flash 高峰 | 输入（缓存未命中）0.30，输入（缓存命中）0.006，输出 1.20 |
| 公式 | 费用 = 缓存未命中输入 × 输入价 + 缓存命中输入 × 命中价 + 输出 × 输出价。推理 token 计入输出。响应没有给出缓存拆分时，全部输入按未命中价计 |
| 区间 | 每个请求都按闲时价计一遍得下限，按高峰价计一遍得上限。没有按请求时刻区分闲时 / 高峰 |
| 缓存处理 | Week 2 的 1197 个有 usage 的请求都给出了缓存拆分。研究 Agent 层的日志没有缓存拆分，全部按未命中价计 |

| 覆盖范围 | **$1.80–3.60 只覆盖账本中有 usage 的 1216 个请求**。7 个超时请求在账本中没有 usage，记为"无法估算"，**不按 0 计**，所以总额不是全部花费。其中 1 个的晚到响应体里有 usage，见 1.1 节 |
| 性质 | 估算，**不是账单**，没有和提供方账单核对 |
| 研究 Agent 的 provider 字段 | 日志记为 `openai`（LangChain 对 OpenAI 兼容客户端的标记）。用量报告按模型名和配置的 DeepSeek 端点解析为 deepseek，原值保留在 `provider_reported` |
