## 1. 调用链（最终代码中的位置）

| 步骤 | 位置 | 说明 |
|---|---|---|
| 1 | `comqutor_alpha/api/routes_research.py` 第 3726 行 | 研究执行时用 `build_server_week2_llm_gateway(run_id, run_dir.parent)` 构造生产网关 |
| 2 | `comqutor_alpha/api/routes_research.py` 第 1072 行 | 调用 `save_structured_agent_outputs(run_dir, llm_gateway=llm_gateway)` |
| 3 | `comqutor_alpha/structure_engine/structured_output_adapter.py` 第 2335 行 → 第 2030 行 | `save_structured_agent_outputs` → `adapt_run_outputs` |

**v1 的状态**：
- v1 文本只保存在 `_RETIRED_TASK_PROMPTS` 中，只供 `retired_prompt_identity_sha256` 计算历史身份。
- 生产代码没有任何地方用它拼 prompt。

## 2. 运行证据（零外部调用）

**新测试**：`tests/test_t4_round34_d1_adapter_citation_contract.py::test_transport_request_asks_for_all_nine_fields_and_scopes_candidates_per_segment`。

它从上表第 2 步的生产入口 `save_structured_agent_outputs` 进入，网关由第 1 步的 `build_server_week2_llm_gateway` 构造，只替换最底层的 HTTP transport。断言内容：
- transport 实际收到的 prompt 含有 “Each item must contain segment_id, claim, evidence, source_section, entities, factors, direction, confidence, and cited_source_id”；
- 语义账本记录的身份是 v2：`prompt_sha256` 等于 `Week2LLMGateway.prompt_identity_sha256("claim_batch_enrichment")`，并且出现在回放登记表 `_SUPPORTED_CALL_IDENTITIES["structured_adapter"]` 中；
- 每个候选来源都是来源登记中的真实条目，带原文摘录，`segment_ids` 恰好是包含该摘录的那些段落；
- 不匹配任何段落的真实来源不会提供给模型。

**修复后的复现**：`01_before_after/after.json`。
- 同样用生产网关构造函数加 `_llm_batch_enrichment`；
- 两份第二次 Fresh 回复的账本身份都是 `week2.claim_batch_enrichment.v2`；
- 请求正文已不同于当时发出的 v1 请求。
