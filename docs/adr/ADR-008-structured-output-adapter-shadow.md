# ADR-008: Structured Output Adapter Offline Shadow

Status:

- `ACCEPTED_FOR_OFFLINE_SHADOW`
- `NOT_LIVE_INTEGRATED`
- `NO_PRODUCTION_AUTHORITY`
- `SEMANTIC_QUALITY_UNPROVEN`

Date: 2026-08-06

## Context and provenance

`SOURCE_FROZEN` — Development Plan v1.0 §5.1 says the Structured Output Adapter converts each Agent's natural-language output into the standard Claim schema and that downstream modules consume structured JSON. It requires `run_id`, `ticker`, `agent`, `claim`, and `evidence`; best-effort factors; optional empty entities; bounded confidence; and safe handling that does not propagate malformed JSON or crash the run. The Plan also requires the original Agent coverage. It does not say every candidate boundary must be generated by an LLM.

`CURRENT_IMPLEMENTATION` — the production Adapter deterministically creates Claim/Evidence boundaries. Its default-disabled Week2 path can enrich selected fields but cannot merge, split, omit, or rewrite those boundaries. This phase does not alter that behavior.

`APPROVED_PROJECT_DECISION` — Phase 1A establishes an offline-only Shadow proposal and evaluation boundary before any live experiment or authority change.

## Decision

1. `extract_claim_segments_with_audit` may be reused read-only as a candidate-hint source. Candidate segments have no Shadow semantic authority.
2. An injected semantic invoker may propose one-to-one Claims, merge adjacent candidates, split a candidate, omit non-substantive text, or abstain.
3. The fixed prompt treats the report as untrusted data and requires strict JSON, atomic Claims, exact half-open source spans, bounded vocabulary, immutable caller identity, and no hidden reasoning or investment-advice fields.
4. The deterministic validator is the sole Shadow admission authority for schema, identity, report hash, source-span fidelity, evidence provenance, source references, factor/direction/source-type vocabulary, claim identity, and output bounds.
5. `shadow_claim_id` is caller-generated from the frozen schema/identity version, run ID, Agent-output ID, sorted source-span offsets, and canonical Claim-text hash. Model-supplied IDs are ignored.
6. Every bundle states `shadow_only=true` and `production_authority=false`. Rejected output produces no fabricated Claim and never falls back to Legacy output under a Shadow label.
7. Automated comparison emits navigation signals and diagnostic candidates only. Human review determines semantic quality; Phase 1A creates no labels or gold set.
8. A future live Shadow phase must persist validated Shadow calls/artifacts before Exact Semantic Replay can consume them. Phase 1A does not modify current Exact Replay.

## Safety and failure behavior

Malformed JSON, invoker failure, validation rejection, valid empty output, explicit abstention, and oversized input have distinct fail-soft statuses. No failure can enter production or call the Legacy Adapter as a substitute Shadow authority.

The parser constructs no Provider, reads no API key, and has no network, Redis, database, route, replay, or historical-output writer. The review builder runs only with an explicit source and output directory; without a fixture it reports `NOT_GENERATED` and makes zero semantic calls.

## Non-goals

This ADR does not integrate a live Shadow path, enable an LLM, change any current prompt, modify the Adapter, Alpha Mapper, Structure Extractor, TradingAgents, canonical prompt injection, Replay, Graph, Activation, Exposure, or Conflict, or switch production authority. It does not implement Evidence Stance, ticker specificity, Counter-Alpha, B2 Conflict admissibility, Clause Graph, dynamic invalidation, or later John requirements.

## Consequence

The repository has an auditable offline contract and human-review harness, but no measured real-model semantic quality. Phase 1B requires independent approval and cannot infer readiness merely from Phase 1A passing.
